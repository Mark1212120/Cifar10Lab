## 2. 模型为什么这样选

使用 `torchvision.models.resnet18(weights=ResNet18_Weights.IMAGENET1K_V1)`，先加载 ImageNet 权重，再将 `fc` 替换为 `Linear(512, 10)`。保留原始 7×7、stride=2 的卷积和 maxpool，不替换 CIFAR stem，避免破坏预训练输入路径。替换分类头后参数量应为 **11,181,642**；实现时用 `sum(p.numel() for p in model.parameters())` 核对。

ResNet-18 结构成熟，预训练权重有官方来源，适合先完成一次结果可信的分类实验。使用外部 ImageNet 预训练必须在结果中明确报告，不能把结果写成仅用 CIFAR-10 从零训练，也不能与此类设置不加区分地比较。

输入采用 96×96，作为速度与保留预训练特征之间的项目折中。这是本次主动设计，**不是该权重的官方默认推理分辨率**；官方默认变换使用更大的 224×224 输入。这里保留 ImageNet 标准化，但自定义训练与评估变换，不直接套用权重的默认 transforms。上采样不会凭空增加 CIFAR-10 的原始细节。

从第 1 轮开始微调整个网络，不设置额外的只训练分类头阶段。分类头使用更大学习率以适应随机初始化，主干使用较小学习率保留预训练信息。

## 3. 硬件适配与边界

实测 GPU 为 RTX 2050、显存 4096 MiB，CPU 为 i7-12650H、内存约 15.71 GiB。按用户要求训练和评估物理 batch 均不超过 4。

| 配置 | 指定值 | 原因 |
|---|---:|---|
| 训练 batch | 4 | 遵守用户上限 |
| 梯度累积 | 8 次 | 完整组聚合 32 张图的梯度，减少更新噪声 |
| 输入 | 96×96 RGB | 比 224×224 减少计算，适配笔记本 |
| 精度 | FP16 autocast + GradScaler | 降低中间激活开销，处理半精度梯度缩放 |
| num_workers | 0 | 避免 Windows 多进程初期问题及额外内存占用 |
| pin_memory | True | 配合 non_blocking CUDA 传输 |
| CPU torch 线程 | 8 | 作为初始设置，避免直接占满所有逻辑线程 |
| torch.compile | 关闭 | 减少 Windows 环境复杂度与编译等待 |
| BN 运行统计 | 冻结 | 避免直接用 4 张图更新运行均值和方差 |

实际峰值显存必须测量。不能只根据 4GB 推断“最大 batch=4”，也不能在未执行前写“已成功训练”。若首轮检查出现 OOM，先排除其他显卡程序；仍不能运行时，唯一预设的资源降级是 batch=2、累积=16，正式开始前更新并保存配置。该情况仍是同一个模型的一次正式实验，不能在已有结果后悄悄改变配置。

## 4. 数据与固定划分

官方 CIFAR-10 包含 50,000 张训练图像和 10,000 张测试图像，原始大小 32×32。类别顺序必须保持 torchvision 的标准顺序：airplane、automobile、bird、cat、deer、dog、frog、horse、ship、truck。

在官方训练集内部按类别分层，使用 `numpy.random.default_rng(42)`：按类别 ID 从 0 到 9 遍历，分别打乱该类原始样本索引，每类取前 500 张作为验证，其余 4,500 张作为训练。保存两个完整索引列表到 `data/cifar10_split_seed42.json`，并记录种子和来源。得到训练 45,000、验证 5,000；验证不与训练重叠，二者并集恰好为原始训练集。

官方测试集 10,000 张保持不动，训练与每轮验证都不能访问它。训练集和验证集可指向同一份原始数据，但必须使用两个不同 transform 的 dataset 实例，避免修改共享 transform 让验证集带上随机增强。

全部数据下载和解压到 `data/`，不复制数据到项目外，不为每次实验重新复制整套图像。首次下载允许 torchvision 做数据完整性检查。

## 5. 输入变换与增强

训练变换顺序固定为：

1. 对原始 32×32 PIL 图像执行 `RandomCrop(32, padding=4)`，默认常量填充。
2. `RandomHorizontalFlip(p=0.5)`。
3. `Resize((96,96), interpolation=BILINEAR, antialias=True)`。
4. `ToTensor()`，像素缩放到 [0,1]。
5. `Normalize(mean=[0.485,0.456,0.406], std=[0.229,0.224,0.225])`。

验证与测试仅执行上述第 3—5 步，不使用随机裁剪和翻转。不使用 MixUp、CutMix、额外外部训练数据、测试时增强或模型集成，让第一次实验便于解释、复现和排查。

## 6. 优化器、损失、轮次

| 参数 | 值 |
|---|---|
| 随机种子 | 42 |
| 总轮次 | 30，每轮遍历全部 45,000 个训练样本 |
| 优化器 | AdamW，betas=(0.9,0.999)，eps=1e-8 |
| 主干基础学习率 | 1e-4 |
| 分类头基础学习率 | 1e-3 |
| 权重衰减 | 5e-4；bias 与归一化层参数不衰减 |
| 训练损失 | CrossEntropyLoss，label_smoothing=0.1，mean reduction |
| 验证 / 测试损失 | 普通交叉熵，label_smoothing=0 |
| 梯度裁剪 | unscale 后按全部可训练参数裁剪，max_norm=1.0 |
| warmup | 前 2 轮，从基础学习率的 0.1 倍线性升到 1 倍 |
| 后续学习率 | 余下 28 轮余弦退火到基础学习率的 0.01 倍 |
| 提前停止 | 关闭；完成预定 30 轮 |

主干与分类头分别按 decay / no-decay 分组，可形成 4 个参数组，每个参数只能出现一次。BN 的 affine 参数仍可训练，但不做权重衰减。每次调用 `model.train()` 后，再将所有 BatchNorm 模块设为 `eval()`；只冻结运行统计，不对整个模型执行 `no_grad()`，也不误冻结其他主干参数。

训练与评估损失的平滑设置不同，因此两条 loss 曲线需明确标注，不把两者的差值直接解读成过拟合程度；准确率均按 logits.argmax 与真实标签计算。

## 7. 梯度累积的执行细节

45,000 / 4 = **11,250 个 micro-batch / 轮**。每 8 个 micro-batch 进行一次优化更新，因此每轮 `ceil(11250/8)=1,407` 次更新；最后一组只有 2 个 micro-batch、共 8 张图。不要丢弃这组，也不要固定除以 8 导致它的梯度变小。

正确约定：一组中的每个 mean loss 乘以“本 micro-batch 的样本数 / 该累积组的实际总样本数”后 backward；完整组每个权重为 1/8，最后一组每个权重为 1/2。每次更新后再清零梯度。日志必须记录未经累积缩放的损失，并按样本数加权平均。

一组内 GradScaler 的 scale 保持一致；完成该组后 `unscale_`、梯度裁剪、`step`、`update`。不要每个 micro-batch 都 optimizer.step 或 scheduler.step，不使用 retain_graph 保存多组计算图。

在没有 AMP 跳步时共 **42,210 次优化更新**，warmup 为 **2,814 次**。调度器按成功的优化更新计数；AMP 检测溢出跳过更新时，不推进学习率计数并记录跳步。频繁跳步或非有限损失应定位问题，不能默默继续产出结果。

设成功更新序号为 u，从 1 开始：前 2,814 次的倍率为 `0.1 + 0.9*(u-1)/(2814-1)`；之后设 `t=(u-2814)/(42210-2814)`，倍率为 `0.01 + 0.99*(1+cos(pi*t))/2`。各参数组基础学习率分别乘以同一倍率。若发生跳步，最终不一定正好到达预定最低学习率，应在日志中据实反映。

梯度累积聚合的是梯度，不会把每次 BatchNorm 实际看到的样本数变成 32；这也是单独冻结 BN 运行统计的原因。

## 8. 随机性与运行检查

对 Python random、NumPy、torch CPU/CUDA 都设置 42；训练 DataLoader 使用独立且可保存状态的 generator，shuffle=True；验证 / 测试 shuffle=False。`cudnn.benchmark=False`、`cudnn.deterministic=True`，确定性算法使用 warn_only 模式。记录警告、软件版本和种子；不能承诺跨显卡与版本逐位一致。

正式训练前，在同一入口做 200 个训练 micro-batch 的检查（25 个完整更新组），不读测试集。验证 shape 为 `[4,3,96,96]`、logits 为 `[4,10]`，loss 有限，分类头与主干都有预期梯度，BN 的 running_mean / running_var 不改变，GPU 确实承担计算。记录 `max_memory_allocated`、`max_memory_reserved` 及 nvidia-smi 总占用，它们含义不同，不混写。

计时前完成 GPU warmup，用 CUDA synchronize 包围计时区间。运行检查后，恢复初始模型（包括随机分类头）、优化器、scaler、调度器和所有 RNG 状态，再开始正式第 1 轮；不能把检查阶段偷偷算成额外预训练。检查日志放在唯一实验目录，不另建一个结果项目。

## 9. 耗时预算与中断恢复

尚未测速，不给出伪精确完成时间。200 个 micro-batch 用于初步估计训练吞吐，首个完整 epoch 的训练加验证时间用于修正总预算。

总耗时约为：安装下载时间 + 运行检查时间 + 30×每轮训练验证时间 + 最终测试绘图时间。以下只是算术情景，不是本机实测：

| 每轮训练加验证耗时 | 30 轮主体耗时 |
|---:|---:|
| 5 分钟 | 约 2.5 小时 |
| 10 分钟 | 约 5 小时 |
| 20 分钟 | 约 10 小时 |

笔记本温度、功耗和后台进程都可能影响速度。默认不动态调整分辨率、模型和轮数；如需要改预算，应在正式实验前明确记录修改。

每轮验证结束保存 `last.pth`，包含模型、优化器、调度器、GradScaler、已完成 epoch、最佳验证指标、配置、Python/NumPy/torch/CUDA RNG 和 DataLoader generator 状态。使用临时文件后原子替换，避免中途断电破坏上一个断点；临时文件也留在同一实验目录。

只支持从完整 epoch 边界恢复，中途断开最多重跑尚未完成的一轮。恢复时核对配置和数据划分；文件已存在时禁止默认覆盖，要求显式 resume。best 和 last 都需明确属于哪个 epoch。

## 10. 模型选择与最终评估

每轮计算验证准确率和普通交叉熵。优先保存验证准确率最高的模型；相同准确率时选更低验证 loss，仍相同则保留较早 epoch。30 轮完成后加载 `best.pth`，在 `model.eval()` 和 `inference_mode()` 下评估官方测试集一次。

需要报告：Top-1 accuracy、macro precision / recall / F1、每类准确率、普通交叉熵、10×10 混淆矩阵。每类 TP/FP/FN 来自同一个混淆矩阵；分母为 0 的 precision 或 F1 定义为 0。准确率记录为 0—1 数值，表格与图表展示时转换为百分比，不能混用。

宏平均 F1 是各类别 F1 的平均，不能用 macro precision 和 macro recall 再求一个 F1 代替。测试集每类 1,000 张，类别顺序保持一致。预测文件记录 test_index、true_label、pred_label、confidence，confidence 为最大 softmax 概率，不等于准确率。

目标为测试准确率达到 90%，尽量更高；未达到也报告真实结果，不伪造曲线、不删除失败结果、不按测试集结果不断换模型。当前决定用预训练 ResNet-18 作为唯一实验，没有预设第二个模型。如果将来要做新实验，应另行明确需求，不能把多次尝试写成只运行一次。
